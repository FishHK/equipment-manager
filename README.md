# 備品管理アプリ — システム仕様書

単一PC・単一ブラウザで使用する、備品の貸出・返却・予約管理アプリです。操作説明は [ユーザー仕様書](USER-SPEC.md)、テストケースは [テストデータ一覧](TEST-DATA.md) を参照してください。

## 1. 実行環境・構成

- HTML・CSS・JavaScriptのみで構成する静的アプリ。外部ライブラリ、ビルド、バックエンド、外部DBは使用しません。
- `index.html` をブラウザで開いて起動します。ブラウザにはlocalStorageとstructuredCloneの対応が必要です。
- 画面切り替えはページ遷移ではなく、単一HTML内のセクションの表示・非表示で行います。
- スクリプトは `test-data.js` → `script.js` の順で読み込みます（defer）。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面・入力欄・一覧表の構造 |
| `style.css` | レイアウト、選択状態、期限超過表示、アイコンの装飾 |
| `script.js` | データ読み書き、入力検証、貸出・返却・予約処理、画面描画 |
| `test-data.js` | サンプルデータ生成と既存保存データの互換処理 |
| `tests/test-data.test.cjs` | Node.jsによる処理の自動テスト |
| `USER-SPEC.md` | ユーザー向け仕様書 |
| `TEST-DATA.md` | サンプルデータの確認ケース |

## 2. データ保存

localStorageのキー `equipment-manager-v1` に、以下の配列を含む1つのJSONオブジェクトを保存します。

```text
employees      社員
items          物品
loans          貸出記録
reservations   予約記録
```

読み込み時にJSONを解析し、各配列の存在・型を確認します。更新時はメモリ上のデータを複製し、変更内容をlocalStorageへ保存できた場合だけ現在のデータを置き換えます。

保存先はブラウザの利用環境に依存します。同じファイルの場所・ブラウザで利用してください。データはGitHubや他のPCへ同期されません。ブラウザの保存データを削除すると失われます。

## 3. データ定義

IDは各配列内で一意の数値です。新規登録時は、その配列の現在の最大ID + 1を採番します。社員・物品のIDは画面に表示しません。

### 社員 `employees`

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `id` | number | 社員ID |
| `name` | string | 社員名 |

同姓同名を許可し、IDで区別します。貸出・予約時の名前直接入力では、既存の同名社員が1件ならその社員を使用し、0件なら追加します。複数件ある場合は一覧からの選択を求めます。

### 物品 `items`

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `id` | number | 物品1個ごとのID |
| `name` | string | 製品名。必須 |
| `model` | string | モデル番号。省略時は空文字 |

物品登録欄の製品名・モデル番号は各100文字以内です。前後の空白を除去します。同じ製品名・モデル番号の物品も別レコードとして登録します。該当する物品が複数ある場合は、配列内の順番で表示名に `(1)`、`(2)` を付けます。表示番号は保存しません。

### 貸出記録 `loans`

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `id` | number | 貸出記録ID |
| `employeeId` | number | `employees.id` を参照 |
| `itemId` | number | `items.id` を参照 |
| `lendDate` | string | 貸出日 |
| `dueDate` | string / null | 返却予定日。旧データでは項目がない場合もある |
| `returnDate` | string / null | 実返却日。未返却はnull |

返却は既存レコードの `returnDate` を更新します。再貸出は新しいレコードを追加し、履歴を保持します。記録する社員は借り手であり、受付担当者・操作担当者は記録しません。

### 予約記録 `reservations`

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `id` | number | 予約記録ID |
| `employeeId` | number | `employees.id` を参照 |
| `itemId` | number | `items.id` を参照 |
| `date` | string | 予約日＝貸出予定日 |
| `dueDate` | string | 返却予定日 |
| `loanId` | number / null | 予約から作成した `loans.id`。未貸出はnull |

予約から貸出すると、貸出記録を作成して `loanId` を設定します。予約編集は同じ予約レコードを更新し、削除は配列から除去します。貸出済みの予約は編集・削除しません。

## 4. 日付・状態判定

日付は `YYYY-MM-DD` 形式で保存します。現在日は端末のローカル日付を使用し、時刻は記録しません。入力日は書式だけでなく実在する日付か確認します。

| 状態 | 判定条件 |
| --- | --- |
| 貸出中 | 対象物品に `returnDate` 未設定の貸出記録がある |
| 倉庫 | 対象物品に未返却の貸出記録がない |
| 有効な予約 | `loanId` 未設定、かつ `date >= 今日` |
| 予約期限切れ | `loanId` 未設定、かつ `date < 今日` |
| 予約から貸出済み | `loanId` が設定済み |
| 社員の返却期限超過 | その社員に未返却かつ `dueDate < 今日` の記録が1件以上ある |

返却予定日がない旧データは期限超過判定から除外します。状態は原則として保存せず、記録と日付から算出します。表示は操作時と60秒ごとに更新します。

## 5. 処理ルール

### 貸出・返却

- 貸出は倉庫にある物品のみ。返却予定日は必須で、本日以降を指定します。
- 貸出ページの返却予定日は起動時・同タブへの切り替え時に今日を設定します。描画更新だけでは入力を上書きしません。
- 本日の予約がある物品は予約者だけが借りられます。予約者が通常貸出から借りた場合も予約と貸出を関連付けます。
- 将来の予約がある場合、返却予定日は予約日より前である必要があります。
- 返却は選択社員の未返却記録を対象とし、実返却日に今日を設定します。
- 期限超過のある社員は赤色と「返却期限超過あり」で表示します。期限超過自体を理由に新規貸出を禁止する処理はありません。

### 予約・編集・削除

- 予約日は本日以降、返却予定日は予約日以降とします。
- 物品ごとに有効な未貸出予約は1件のみ。日付が離れていても複数の有効予約は作成できません。
- 貸出中の物品を予約する場合、既存の返却予定日より後の予約日が必要です。返却予定日不明の場合は予約できません。
- 本日の予約のみ「予約から貸出」に表示します。現物が未返却なら貸出処理を拒否します。
- 編集は一覧の鉛筆から予約画面へ移動し、社員・物品・日付を初期入力します。「変更を保存」で更新します。
- 編集時の重複判定から編集対象自身を除外します。新規予約と同じ日付・貸出状況の検証を行います。
- ゴミ箱で未貸出予約を削除します。キャンセルは編集内容を保存せず一覧へ戻します。
- 期限切れ予約も編集・削除可能ですが、変更保存時の予約日は本日以降にする必要があります。

## 6. 画面・検索

タブは貸出、返却、予約、予約状況、予約から貸出、物品登録、物品一覧、記録の8種類です。

- 貸出・予約：社員名、製品名・モデル番号の検索。前後の空白を除去し、大文字・小文字を区別しない部分一致です。
- 返却・予約から貸出：社員と物品の双方向選択。最初に選んだ側を基準に相手側を絞ります。物品選択時は社員を自動入力し、「選択解除」で全件へ戻します。検索欄は表示しません。
- 物品一覧：製品名・モデル番号・借り手名で検索。状態、借り手、貸出日、返却予定日を表示し、予約者・予約日の列は設けません。
- 予約状況：予約者・製品名・モデル番号・予約日で検索。「予約中」「本日」「すべて」で絞り、予約日昇順に表示します。「本日」には当日分の貸出済み予約も含みます。
- 記録：社員名・製品名・モデル番号で検索。貸出記録と予約記録をそれぞれ追加順の逆順で表示します。両者を統合した日時順ではありません。

## 7. 初期データ・エラー処理

初回は社員40件・物品40件を作成し、追加のシナリオデータを一度だけ投入します。新規環境の合計は社員55件・物品67件・貸出記録16件・予約10件です。シナリオの日付は初回投入日を基準とし、再起動しても変更しません。

読み込み・初期保存に失敗した場合は警告を表示し、データ更新を停止します。操作中の保存失敗はエラーを表示し、変更を現在のデータへ反映しません。

ユーザー入力の表示にはtextContentを使用します。アイコンのSVGは固定文字列です。

## 8. 検証と対象範囲

```powershell
node --check script.js
node --check test-data.js
node tests/test-data.test.cjs
```

Node.jsは開発時のテストのみで使用します。自動テストは簡易DOMと保存領域を使い、貸出・返却、予約編集・削除、重複防止、絞り込み、保存後の再読み込みなどの処理を確認します。実ブラウザの表示・レイアウト検証は含みません。

現在の対象外：ログイン・権限制御、複数PC／複数タブ間の競合制御、サーバー同期、自動バックアップ、データのインポート／エクスポート、社員・物品の編集／削除。保存データの参照整合性はアプリの処理で管理し、DBによる制約はありません。
